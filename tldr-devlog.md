A condensed walkthrough of how `rparth` was built. The full reasoning lives in each commit
body (the project uses commit messages as a development log on purpose — see the README's
"For the interviewer" note). This file is the short version, oldest commit first.

## At a glance

- **Approach**: build a working MVP skeleton first, then layer features (config → server →
  observability → caching), then polish (CI, Docker, docs, streaming fix).
- **Recurring technical decisions**:
    - **No HTTP/2 upstream** — would lower TCP connection count but complicates the streaming
      response path the proxy relies on. Worth it in real life, not for this exercise.
    - **No WebSocket** — this another protocol which is not http and need L4 routing. Only handshake is http.
    - **Streaming-first** — responses are streamed to the client; compression is disabled and
      (later) every write is flushed so SSE/long-running requests don't stall.
    - **Behavior-focused BDD tests** (Ginkgo + Gomega), generated mocks (mockgen) over
      hand-written fakes, loose expectations.
- **AI workflow** (per README): writes most code himself, uses AI mainly for tests, docs, and
  review — always reviewing, trimming, and triaging the output rather than accepting it wholesale.

## The journey, commit by commit

### 1. `feat(MVP): Init an MVP`

The skeleton: a reverse proxy implementing `http.Handler`, route model, and a tuned default
transport (connection-pooling params validated with AI). Key calls made here:

- **HTTP/2 not forced** (streaming complexity > benefit for this exercise).
- **Hop-by-hop headers sanitized** before hitting the backend — which also rules out WebSocket
  (an accepted trade-off).
- **`X-Forwarded-*` headers** and **per-route timeouts** (via context timeout) added.
- Picked **Ginkgo/Gomega** for readable BDD tests, **slog** for logging (first use; chosen after
  checking what the current Go logging story is), and **golangci-lint** configured to taste.
- AI review caught the main bug: **`Host` lives in `req.Host`, not the header map** — fixed.

### 2. `feat: wire YAML config and Kong CLI`

CLI flags + config loading. **Kong** for arg parsing (struct tags, no manual parsing).
**goccy/go-yaml** instead of the now-archived `go-yaml/yaml`, using the unmarshaler pattern to
validate and fill structs — including a custom unmarshaler for `url.URL` in route config.
Structure: `main` (flags/commands/config) → `app` package as the dependency-injection startup.
Log config added up front, with JSON output option (best for runtime log collection/analysis).

### 3. `feat(app): graceful/force shutdown + HTTPS`

TLS is table stakes in production, so it's added. Graceful shutdown via the author's standard
pattern: SIGINT/SIGTERM context → run server in goroutine → on signal, shut down with a wait
channel; a **second signal forces an immediate stop** (mostly a dev convenience).
Added an HTTP-server-and-listener **builder seam purely for testing** so `httptest.Server` can
drive the proxy.

### 4. `feat(observability): request logs + Prometheus metrics`

Middleware-based observability. Access logs via `go-chi/httplog` (no point hand-rolling).
Prometheus added with a **metrics middleware** (request count + duration) and a **dedicated
`/_metrics` middleware** that short-circuits the chain (avoids pulling in a router just for one
endpoint). Also added upstream request counters/duration to tell "slow backend" from "slow
proxy". AI flagged unbounded **metric cardinality / memory growth** → made the path-value
function injectable to keep label cardinality down. Also corrected the no-backend status to
**502**.

### 5. `feat(observability): label logs/metrics by route name`

To attribute logs and metrics to a route, route data is passed between middlewares via
`context.WithValue`. Refactored the proxy: a middleware puts the matched route on the context,
and the proxy reads it from there instead of re-matching. Route name added to the access log
format and used as the metrics label (also fixing the earlier memory-growth concern).

### 6. `feat(cache): MVP caching`

Cache interface + entry struct + middleware. **LRU-with-expiration** store (hashicorp lib) to
bound memory — entries capped at **1 MiB** each, ~100 entries, so worst-case cache memory is
predictable (<100 MiB). Only `GET` is cached. The real `ResponseWriter` is proxied so caching
doesn't disturb streaming. Cache **key uses xxhash** (fast, low collision) over the obvious bits
plus **`Authorization`/`Cookie`** so user A can't read user B's cached response. AI review
prompted honoring **`Cache-Control` and `Vary`** directives. Still missing: telling the browser
it can cache (next commit).

### 7. `feat(cache): Redis backend + ETag revalidation`

- **`ETag` on cache hits** so the browser can revalidate.
- **Per-route `no_cache` flag** — admin decides cacheability, instead of everything being
  hardcoded/forced.
- **Redis backend** for multi-instance deployments (shared cache, no per-instance duplication).
  Refactored the cache interface to **close the Redis client cleanly** on app stop. Deliberately
  **no dependency injection** for the Redis client — only needed here, DI would add needless
  complexity.

### 16. `feat(proxy): real-time streaming via per-chunk flush`

A global review surfaced a missed case: **SSE / long-running requests**. Plain `io.Copy` let the

workflows.

## Threads that run through the whole log

- **MVP-then-layer**: ship a working skeleton, add features in dependency order, polish last.
- **Streaming is the backbone**: HTTP/2, compression, and the final flush fix all trace back to
  keeping the response stream unobstructed.
- **Bounded resources**: LRU size + per-item cap make cache memory predictable; transport pooling
  is tuned deliberately.
- **Observability is first-class**: metrics and logs are labeled per route, errors are classified
  by reason, cache skips are explained — built for a real Grafana/ops view.
- **Tests stay behavioral**: Ginkgo/Gomega, generated mocks, loose expectations, redundant specs
  pruned.
- **AI as a reviewer/assistant, not an author**: used for tests, docs, and review; output always
  triaged and trimmed by the author.
